# Audit and Refinement

Read [project instructions](../../../AGENTS.md), [project context](../../../docs/project-context.md), and [QA guidance](../../../docs/agents/qa.md). Use the actual current artifact and supplied prototype. Report missing evidence instead of inventing observations.

This retains the existing skill's systematic inspection and prioritized improvement role. The workflow is report-first unless implementation is already assigned. The retained skill name does not authorize a whole-site redesign; the original MIT notice is preserved in `LICENSE`.

## Inspect and classify

Inspect the assigned area and dependencies enough to explain behavior. Cover relevant hierarchy, type, layout/overflow, theme/contrast, focus/navigation, feedback, content accuracy and motion lifecycle/fallbacks. Cite actual source locations or observed states; label source-based hypotheses.

- Requirement regression: a verified departure from an owner requirement or supplied reference.
- Functional/usability defect: a reproduced or evidenced issue affecting the visitor's task.
- Unverified risk: a concrete concern needing a specified check.
- Optional refinement: a preference or improvement needing a scope decision.

Prioritize blocked content/navigation, inaccessible interaction, broken loader/fallback and official-asset regressions ahead of aesthetic preferences. Do not derive severity from a generic style score or close a known caveat without new evidence.

## Act within scope

Return each useful finding with path/line or state evidence, impact, smallest recommended change, affected requirement and acceptance check. For an audit, deliver the report. For already-assigned fixes, implement and verify the scoped change without asking again unless the necessary solution expands scope.

Do not prescribe global font swaps, spacing doubles, stock-image quotas, automatic texture, new scrolling systems, hover movement, invented personal claims or unrelated sections. Preserve the supplied wave, loader, wordmarks and composition. Add legal/cookie UI only for a concrete product requirement.

Use `design-taste-frontend` when visual judgment is needed without repeating its entire review. Hand substantial work to the coordinator using [workflow and ownership](../../../docs/agents/workflow.md). Return actual checks, outcomes, unresolved limitations and any specific decision needed. A clean audit does not authorize publication.
