# Project visual judgment

Use the project's approved artifact to establish composition and identity. Use current screenshots for observed rendering. Keep the two evidence types distinct.

## Layout and typography

- Compare the same viewport, theme, content, and loaded state. Note the actual source of an issue: changed font metrics, line wrapping, width constraint, spacing, alignment, cropping, or stacking order.
- Preserve the relative hierarchy of name, supporting copy, portrait, controls, and introduction. A request to fix one spacing issue is not permission to replace the landing layout.
- Keep text readable and intentional across narrow/short viewports and zoom. Do not remove content or force nonwrapping text just to hide overflow.
- Derive any proposed token consolidation from inspected V2.1/current values. Preserve font/weight/line-height and layout relationships unless the assignment authorizes changing them. Do not swap a font merely because a generic guide dislikes it.

## Color, surfaces, and branding

- Keep the contract's backdrop, themed wave colors, official wordmarks, and supplied favicon variants. Diagnose theme mismatches through actual style/state ownership.
- Evaluate contrast and focus visibility in the affected theme/state. Preserve the approved hover glow while keeping size and position stable.
- Intentional texture, rules, centered text, gradients, or glow are judged in context. Generic bans are not portfolio requirements; neither are automatic requests to add those effects.

## Imagery and content

- Use the owner's actual subject and supplied assets. Preserve the current portrait treatment; the final portrait itself remains an open content decision.
- Do not replace official vector marks, add stock portraits, or invent personal projects, client brands, testimonials, metrics, dates, or destinations. Keep existing placeholders visibly identified until resolved.
- Add imagery only when requested content needs it. License and credit requirements belong to each asset; an MIT skill license does not license third-party photos.

## Interaction and report

Use actual menu/focus, theme, navigation, and social-feedback interactions relevant to the change. Inspect clipping, readable overlays, hit targets, focus return, and reveal-once content. A screenshot cannot prove keyboard behavior.

For each finding provide: observed state, expected contract or user outcome, source/evidence location, user impact, and smallest useful change. Separate defects from optional visual preferences. For a proposal crossing the approved baseline, prepare a concrete before/after explanation for owner approval before implementation.
