# Ideas Organizer

Read [project instructions](../../../AGENTS.md) and [project context](../../../docs/project-context.md). Use the owner's current assignment and actual files to establish the requested outcome, scope and mode. This skill is specific to Ranz.dev; keep shared project requirements in those documents.

## Match the request

An explicit plan or audit produces a brief/report only. Within already-authorized implementation, organize the work and continue within that authorization without inventing another approval gate. A clear bounded edit may need only a short outcome and acceptance check.

Use the conversation and inspected evidence before asking questions. Distinguish owner requirements, verified facts, hypotheses, recommendations and missing decisions. Ask only for information that changes the next meaningful action. Continue independent work while a necessary answer is pending.

## Prepare a useful brief

- State the observable outcome, requested mode and existing authorization.
- Identify actual affected files/areas, dependencies and reference behavior to preserve. Do not invent paths, commands, installed dependencies, personal content or test results.
- Break substantial work into dependency-ordered tasks. Keep layout/content, motion lifecycle and verification ownership clear. Refinement does not authorize a new art direction.
- Define observable acceptance, such as a stationary header glow, a completed mark held before full wave coverage, restored menu focus, or no-flash completed refresh. Choose checks relevant to the assignment.
- Mark material unresolved decisions and disclose sensible assumptions. Do not infer package versions, mobile acceptance or publishing permission.

Use the [handoff workflow](../../../docs/agents/workflow.md) when a specialist would help. `web-prod` coordinates substantial work when available; the main agent owns user approvals and integration. Simple tasks stay with one agent. Do not install missing agents or claim delegation from a configuration file's presence.

Return the shortest useful brief with outcome, scope/constraints, dependencies, ownership, acceptance and unresolved decisions. State whether work can proceed within existing authorization or which specific decision blocks a dependent part. Persist only decisions that need to outlive the task.
